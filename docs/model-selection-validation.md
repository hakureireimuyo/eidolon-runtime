# 模型选型与本地验证

> 本文档记录"模型角色 / 本地验证"方向的**最终决策**(已剔除过渡讨论)。它给出在有限硬件下验证架构的方法论与结论性硬件指导。
> 相关文档:[状态模型、上下文管理与缓存](./state-and-context.md) · [运行时核心设计](./runtime-core-design.md)(另见:核心架构哲学与项目定位)

## 1. LLM 与角色一致性的相关性降低

状态完全由系统控制后,换模型(GPT / Claude / Gemini / 开源)不改变核心行为,只影响"表现层人格":

- 语言风格、隐喻能力、对复杂情绪的表达、对潜台词的理解、长程推理能力。

类比影视制作:编剧 / 导演 = 系统,演员 = LLM；演员可换而角色不失忆、人格不崩溃。因此**决定效果上限的主要是状态建模与上下文生成质量,而非模型大小**。

## 2. 用"小模型"验证架构正确性(关键方法论)

- 验证的不是"模型写不写得出惊艳小说",而是"**外部状态系统能否控制模型行为**"。
- 小模型是更严格的测试:若 3B 模型在状态注入下仍能保持角色一致 / 情绪连续 / 关系合理,则换更强模型只提升表达,不改变核心行为。反之若只有大模型能维持人格,说明状态系统尚未真正接管。
- 类比游戏引擎:先用简单 AI 验证行为树 / 状态机是否正确,再接超级智能 NPC。

## 3. 本地验证硬件指导(结论性)

| 配置 | 定位 | 推荐模型 | 上下文 |
|------|------|---------|-------|
| 16GB + RTX 3050 (4GB) | 验证架构 | 1.5B~4B 量化(如 Qwen2.5-3B Q4) | 4K~8K,GPU offload + CPU 承担部分 KV Cache |
| 32GB + RTX 5060 (8GB) | 正式开发 | 7B~8B(如 Qwen3-8B Q4),可试 14B | 8K~16K |
| 24GB 显存(如 4090) | 进阶 | 14B~32B 舒适区 | 视显存 |

只需替换 `llm.generate()` 接口,模型隔离在 **LLM Adapter** 之后；本地 / 服务器配置切换不影响运行时。

## 4. 上下文需求反而更低

目标不是"无限上下文 AI",而是"**有限上下文下仍具长期连续性的 AI**"——百万 token 历史经记忆系统压缩为 `trust=0.73` 等参数 + 约 3000 token 上下文。因此超长上下文非必需,状态系统才是关键。
