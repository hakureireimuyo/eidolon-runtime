# 人格、意图与认知链:图内的认知分层

> 本文档定义角色认知在图中如何分层落地:**人格决定倾向,状态决定当下,意图决定方向,行为与表达决定实现**——人格与意图都是图中的状态转换环节与状态,而不是 Runtime 特殊理解的黑盒。
> 相关文档:图运行时总纲(`eidolon-graph` 仓库 `docs/graph-runtime-overview.md`) · 节点类型(`eidolon-graph` 仓库 `docs/graph-node-types.md`) · 资产系统(`eidolon-graph` 仓库 `docs/graph-assets.md`) · [应用模式与场景图式](./graph-application-patterns.md)

## 1. 核心命题

> **认知链:人格决定倾向,状态决定当下,意图决定方向,行为与表达决定实现。**

```
世界状态 / 事件
      │
      ▼
┌────────────┐
│   人格矩阵   │ ← Personality Asset(倾向:如何评价、感受、选择)
└─────┬──────┘
      │
      ▼
┌────────────┐
│   意图生成   │(当前这一刻想让世界发生什么)
└─────┬──────┘
      │
   Intent State(世界事实)
      │
 ┌────┴────┐
 ▼         ▼
行为决策    表达决策
 │         │
 ▼         ▼
世界行为    LLM → 文本
```

旧的"Personality Core"路线把人格、情绪、记忆、关系、需求、目标、注意力、动机全部塞进一个不可替换的核心;图模型把它们拆成**节点、状态和资产**——人格从"系统本体"降级为"世界中的一种可运行结构"(可编辑、可观察、可替换)。

## 2. 人格与意图的分工

| | 回答的问题 | 形式 |
|---|-----------|------|
| **人格矩阵** | 面对不同情况,我倾向于如何**评价、感受和选择**? | 资产(版本化,见 资产系统(`eidolon-graph` 仓库 `docs/graph-assets.md`) §2.3) |
| **意图矩阵** | 在当前这一刻,我究竟想**让世界发生什么**? | 图中的状态转换 |

二者不能混在一起——**人格 ≠ 意图**:

- 人格 → 影响意图生成;
- 意图 → 决定行为方向;
- 行为 → 决定具体做什么;
- 表达 → 决定具体怎么说。

同一意图经不同人格产生不同行为:意图都是"帮助这个人",善良角色直接提供资源并承担风险,谨慎角色先确认信息、小规模帮助、避免暴露,自私角色要求交换、获取未来利益。同一个人格在不同状态下也会产生完全不同的意图。

## 3. 意图是图中的状态

意图生成的结果不是内部临时变量,而是**世界事实**(`Intent State`):

```
character.alice.intent = {
    primary: "escape",
    secondary: "hide_information",
    target: "bob",
    urgency: 0.83
}
```

任何节点都可以读取它:

- 剧情系统读取:Alice 的意图是逃跑 + 目标是地下室 + Bob 不知情 → 触发剧情节点;
- 其他角色读取:Alice.intent = escape → Bob 的人格系统重新计算 → Bob.intent = intercept。

于是多角色之间根本不需要 `Agent A → 调用 Agent B`,而是 `Alice → Intent → World State → Bob → Intent`——**多角色世界内部自然发生因果链**,意图的读写遵守全局变量的同一套拉取语义(读不唤醒、写经输出绑定)。

## 4. LLM 的干净位置

LLM 被限制在认知链的最后一层:

```
人格 → 意图 → 表达意图 → LLM → 语言
```

| 问题 | 由谁负责 |
|------|---------|
| 我到底想不想说? | 意图系统(不归 LLM) |
| 我为什么要说? | 意图系统(不归 LLM) |
| 怎样说最自然? | **LLM** |
| 这个意图在当前世界规则下如何实现? | 行为节点(程序) |

LLM 收到的是经过人格与意图处理之后的**结果**(如主导意图 = 反击,次级意图 = 试探底线),它只需要把已确定的意图与状态翻译成语言——"你最好再说一遍。"

## 5. 图内落点

```
                世界状态 ─────┐
                关系状态 ─────┤
                历史事件 ─────┼→ [人格偏置节点] ← PersonalityAsset
                需求状态 ─────┤
                目标状态 ─────┘
                        │
                        ▼
                   [意图生成器]
                        │
                   Intent State
                        │
             ┌──────────┴──────────┐
             ▼                     ▼
        [行为决策节点]          [表达决策节点]
             │                     │
             ▼                     ▼
          世界行为                [LLM 节点]
            (做)                    │
                                    ▼
                                  文本(说)
```

- 人格偏置节点是**普通节点**:未实现时系统照常运行(先用固定权重占位),实现后按 节点类型(`eidolon-graph` 仓库 `docs/graph-node-types.md`) §7 的协议稳定原则自由迭代(V1 固定向量 → V2 偏置矩阵 → V3 动态矩阵 → …),上层图零改动;
- 同一个世界可以同时挂不同人格实现:角色 A = 简单人格节点、角色 B = 偏置矩阵节点、角色 C = LLM 人格节点、角色 D = 用户自定义人格子图;
- 表达之外的输出同样由意图驱动:行为状态可扇出到表情矩阵(立绘)、场景节点、控制信号(见 [表现状态与输出适配](./graph-presentation-output.md))。

## 6. 理论边界

- 人格矩阵**不承担"善恶真理"的定义**,只表达价值函数、行为偏置与状态转换倾向;"什么行为最终发生"仍由图中的决策节点、世界规则、资源约束、随机性共同决定;
- 一个极其善良的角色,在 `资源 = 0`、`生命危险 = 极高`、`保护对象 = 自己的孩子` 的情境下仍可能做出攻击行为——若人格矩阵直接等价于"善良 = 永远帮助别人",模型就退化成新的 Prompt 工程;
- 人格矩阵的训练目标因此非常明确且小:**给定世界状态、事件、角色状态与候选意图,人格应该如何改变这些意图的优先级与选择概率?**——不需要训练成"会聊天的人格模型",甚至不负责最终语言生成。

## 7. 可测试性与可回归性

```
World + Rules + State + RNG + Personality Asset → Trajectory
```

- 人格资产相同、其他输入完全相同 → 行为轨迹**可复现**;
- 只替换人格资产 → 产生的轨迹差异**可归因于人格模型本身**;
- 旧存档可以继续使用旧人格资产,新世界升级新版本——比"换一个 system prompt 看看是不是更善良了"严格得多,人格模型第一次具备了软件工程意义上的可测试性和可回归性(与 持久化与编辑(`eidolon-graph` 仓库 `docs/graph-persistence-and-editing.md`) §3.2 的 RNG 持久化同源)。
