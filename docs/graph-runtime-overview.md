# 图运行时总纲:节点、信号与世界蓝图

> 本文档定义系统核心的定位:**运行时是一个图运行时——用户编辑的图就是世界的运行蓝图,引擎解释它、世界照着它运转。**
> 相关文档:[执行模型](./graph-execution-model.md) · [端口、绑定与控制信号](./graph-ports-bindings.md) · [节点类型](./graph-node-types.md) · [资产系统](./graph-assets.md) · [持久化与编辑](./graph-persistence-and-editing.md)

## 1. 核心命题

> **系统是一个游戏引擎:引擎运行用户编辑的规则,世界按照被设计的意图运转。管理的主体不是资源,而是文本、数据、规则与能力节点。**

```
游戏引擎:   用户编辑场景 → 引擎运行规则 → 渲染器生成画面
本系统:     用户编辑图 → 引擎运行规则 → LLM 渲染为文字
```

- 游戏引擎中,场景是用户编辑的产物,引擎解释并运行它;
- 本系统中,**图(用户编辑的产物)就是世界的运行蓝图**,引擎是图解释器;
- LLM 只是图中的一类节点(表现器官),可换、可关,不承载真实性——与既有文档"LLM 是渲染器"的定位一致。

## 2. 核心概念

| 概念 | 含义 |
|------|------|
| **图** | 世界运行蓝图:节点实例 + 连线 + 绑定,是用户编辑的产物 |
| **节点** | 状态转换器:读输入、改自身状态、写输出;内部实现黑盒(程序或 LLM) |
| **数据包(数据通道)** | 沿数据连线流动的数据;数据到达 = 触发 |
| **控制信号(控制通道)** | 无载荷的电平信号:门控与屏蔽,与数据严格分离 |
| **连线** | 数据流动方向 = 触发方向;一条输出可扇出到多个输入 |
| **节点内部状态** | 节点自维护的数据("权重"),世界事实的分布式存储 |
| **资产** | 命名的声明式对象:全局变量、常量、节点类型、图 |
| **轮次(tick)** | 世界的心跳;每轮全图同步推进一拍 |

## 3. 与既有设计文档的关系

图模型不是推翻既有架构,而是它的落地形态:

| 既有概念 | 图模型中的对应 |
|---------|--------------|
| Processor(状态转换器) | 节点 |
| Event(状态变化的原因) | 信号(数据包) |
| State Store(共享状态) | 分布式:节点内部状态 + 全局变量资产 |
| Event Bus(事件分发) | 连线传播(用户显式设计的分发路径) |
| 引擎 = 流动的管理者 | 图运行时:连线的解释者 |
| Context Compiler | 普通节点(子图):数据 → 上下文 |
| LLM 反向指挥程序 | 工具调用节点 / 程序验证节点 |

与演化路线的关系:一至三阶段(State/Event 骨架、多处理器协同、反向控制流)在图模型中统一为"建图";四阶段(Extension Registry)即节点类型资产;五阶段(Scheduler/Planner)是图中挂载的调度节点;六阶段(多模态)是新的昂贵节点类型。

## 4. 循环是连线的涌现,而非系统原语

- 图**没有**强制的起点和终点:起于信号源(时钟、聊天输入、动作输入),终于吸收(节点不改变或输出不再被消费);
- **循环不是引擎强加的自循环,而是用户连线的产物**:一条反馈连线就是一个循环,没有反馈连线就没有循环;
- 拓扑层不设限:死循环、无源环、纯反馈环都是合法的用户设计,引擎不禁止;
- 执行器只保底"不挂起"(见 [执行模型](./graph-execution-model.md)),编辑器只做静态提示(无源环永不自发触发、无门控环每轮空转),提示不是禁止。

## 5. 节点内部是黑盒,LLM 只是节点的一种

- 节点对外只有契约:输入端口、输出端口、状态与配置字段。内部是程序还是 LLM、是单节点还是嵌套子图,一概无关;
- LLM 节点只是"昂贵的节点":不关心数据在哪,只关心被传入了什么、传给哪个接口、产出什么;
- **上下文管理是一条可编辑的节点链**:

```
[状态节点们] →(可选:RAG / 向量检索 / 记忆压缩)→ ContextManager 节点 → LLM 调用节点
```

"被管理上下文注入"因此完全可见:LLM 能收到什么,看它的上游连线即可,没有隐藏通道。链上接什么(要不要记忆压缩、接几个检索)是用户的编辑。

## 6. 被否定的方案

- ❌ **直接依赖 LangGraph**:per-invocation 执行(世界需要无人调用时持续运转)、以 LLM 调用为中心的节点编排(LLM 应是节点之一而非节点之核)、编译期静态图(世界规则需可编辑为数据)。借用其"图与状态"的范式,自研执行内核。
- ❌ **共享黑板(Blackboard)**:数据写入的消费时机不确定,链路不显式。改为:数据随信号沿连线流动,节点内部自维护状态。
- ❌ **强制单一入口/出口**:改为任意信号源与吸收点,循环由连线涌现。

## 7. 核心原则汇总

1. **规则与事实分离**:图(规则)是资产,节点状态(世界事实)是快照,分开存储;改图不动事实。
2. **一切显式**:数据链路、读取引用、控制信号全部可见于图,没有隐藏通道。
3. **确定性优先**:同步轮次 + 轮初读轮末提交,节点执行顺序与结果无关。
4. **节点协议是唯一边界**:实现节点协议 = 注册为能力,运行时只认接口不认实现。
