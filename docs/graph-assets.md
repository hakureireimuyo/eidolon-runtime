# 资产系统:声明式资产与全局变量

> 本文档定义资产系统:**一切可被图引用的东西都是资产;资产必须声明(状态类资产必须带默认值)才能使用;引用即校验。**
> 相关文档:[图运行时总纲](./graph-runtime-overview.md) · [节点类型](./graph-node-types.md) · [持久化与编辑](./graph-persistence-and-editing.md)

## 1. 核心命题

> **资产 = {kind, name, 声明}。未声明的名字不存在,引用即非法。**

## 2. 资产种类

| kind | 声明内容 | 持久化 |
|------|---------|--------|
| 全局变量 | 类型(可选)+ **默认值(必需)** | 是(世界快照) |
| 常量 | 类型(可选)+ 值 | 否(永远是声明值) |
| 节点类型 | 接口契约 + 实现绑定(见 [节点类型](./graph-node-types.md)) | 是(图资产,版本化) |
| 图 | 节点实例 + 连线 + 绑定 | 是(图资产,版本化) |
| 服务/连接 | 连接参数(DSN、凭证引用、配置) | 声明持久化,连接本身是运行时资源 |

**kind 开放**:资产的定义可以是任何东西,上表是 V1 内置的五类,未来可扩展。

角色包(既有文档中的资产集合概念)= 图 + 节点类型 + 全局变量打包;角色包加载 = 资产注册 + 引用校验。

### 2.1 服务类资产:数据库连接也可以是资产

记忆系统需要数据库——**数据库连接本身作为一种资产被声明和传递**:

```
memory_db: 服务资产 { kind: sqlite, dsn: "..." }
记忆节点: 配置字段 db → 引用资产 "memory_db"
```

- 声明持久化的是**连接参数**(DSN、凭证引用、配置);连接本身是运行时资源,由引擎在加载图时建立、卸载时关闭;
- 节点通过**配置字段**引用服务资产,节点内部经该引用拿到连接——记忆节点不硬编码数据库地址;
- 与其他资产一致的规则:先声明后引用,未声明引用在编辑事务提交时抛异常;
- 好处:可分享、可替换(换环境只改一处声明)、编辑器可见,图与具体服务解耦。

## 3. 全局变量

全局变量是**命名状态槽**,是"数据不走黑板"原则的唯一例外,受以下约束收敛:

### 3.1 声明

- 必须声明(名字 + 类型 + **默认值**)才能被引用;
- **未声明引用 → 编辑事务提交时抛异常**,运行时加载图资产时再校验一遍(防手工改资产文件绕过编辑器)。

### 3.2 语义

- **读取不唤醒**:全局被改不触发任何节点;读取它的节点在下次因其他原因开火时取最新值(拉,不是推);
- **写入**经输出端口的全局写入绑定完成,轮末统一提交;
- **多写者:last-write-wins**——轮内按节点在图资产中的声明顺序应用,后者覆盖前者;跨轮按轮次自然有序;同一节点多个输出写同一全局 → 校验报错。编辑器对多写者给出告警(编辑层的提示责任),运行时不做硬限制;
- **轮初读、轮末提交**:单写者场景下写入顺序与节点执行顺序无关;多写者是唯一的保序依赖,属编辑器应提示避免的边缘路径。

## 4. 资产相关校验(编辑事务提交前)

1. 所有绑定引用的资产(全局变量/常量/服务)已声明(否则抛异常);
2. 全局变量声明必须带默认值;
3. 输出绑定指向的资产必须存在;
4. 同一节点多个输出绑定同一全局 → 报错。

完整校验清单见 [持久化与编辑](./graph-persistence-and-editing.md) §5。

## 5. 资产与运行时

- 资产是数据:编辑器是资产的第一个消费者,运行时是第二个——**资产格式先于编辑器存在**,编辑器只是"图数据的可视化编辑界面";
- 资产可分享、可打包、可版本化;节点类型资产与图资产分离,类型可复用;
- 图资产中的声明顺序承载全局写序语义,资产格式必须保留声明顺序。
