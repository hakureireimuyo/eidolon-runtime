# 资产系统:声明式资产与全局变量

> 本文档定义资产系统:**一切可被图引用的东西都是资产;资产必须声明(状态类资产必须带默认值)才能使用;引用即校验。**
> 相关文档:[图运行时总纲](./graph-runtime-overview.md) · [节点类型](./graph-node-types.md) · [持久化与编辑](./graph-persistence-and-editing.md) · [人格、意图与认知链](./graph-cognitive-chain.md) · [表现状态与输出适配](./graph-presentation-output.md)

## 1. 核心命题

> **资产 = {kind, name, 声明}。未声明的名字不存在,引用即非法。**

## 2. 资产种类

| kind | 声明内容 | 持久化 |
|------|---------|--------|
| 全局变量 | 类型(可选)+ **默认值(必需)** | 是(世界快照) |
| 常量 | 类型(可选)+ 值 | 否(永远是声明值) |
| 节点类型 | 接口契约 + 实现绑定(见 [节点类型](./graph-node-types.md)) | 是(图资产,版本化) |
| 图 | 节点实例 + 连线 + 绑定 | 是(图资产,版本化) |
| 服务/连接 | 连接参数(DSN、凭证引用、配置) | 声明持久化,连接本身是运行时资源 |
| 知识资产 | 原文/切分/向量索引的引用(见 §2.2) | 是(版本化;索引可重建) |
| 数据(模型)资产 | 矩阵、参数等可计算对象(如人格矩阵,见 §2.3) | 是(版本化) |
| 媒体资产 | 图片/音频/视频资源引用(见 §2.4) | 是(版本化) |

**kind 开放**:资产的定义可以是任何东西,上表是 V1 内置的八类,未来可扩展。

**卡带/项目 = 可执行世界的打包**:图资产(世界规则)+ 节点类型(世界能力)+ 全局变量定义(世界状态接口)+ 知识资产(世界知识)+ 媒体资产(世界表现资源)+ 服务资产(外部能力)。用户最终拿到的不是一个"角色卡",而是一个**可执行世界**——角色卡只是最小规模的世界资产;卡带加载 = 资产注册 + 引用校验。开发者→节点类型→图资产→打包→用户→修改图→重新运行/分发的链条,让用户级编辑分发成为可能。

### 2.1 服务类资产:数据库连接也可以是资产

记忆系统需要数据库——**数据库连接本身作为一种资产被声明和传递**:

```
memory_db: 服务资产 { kind: sqlite, dsn: "..." }
记忆节点: 配置字段 db → 引用资产 "memory_db"
```

- 声明持久化的是**连接参数**(DSN、凭证引用、配置);连接本身是运行时资源,由引擎在加载图时建立、卸载时关闭;
- 节点通过**配置字段**引用服务资产,节点内部经该引用拿到连接——记忆节点不硬编码数据库地址;
- 与其他资产一致的规则:先声明后引用,未声明引用在编辑事务提交时抛异常;
- 好处:可分享、可替换(换环境只改一处声明)、编辑器可见,图与具体服务解耦。

### 2.2 知识资产:世界知识的外部只读数据源

世界观、人物设定、小说原文不必塞进巨大 Prompt——它们经过管线成为**可检索的知识资产**:

```
Novel Asset → 文本切分 → Embedding → Vector Store → 知识资产
```

- 图内的检索节点按需查询:角色状态 / 世界状态 / 当前事件 / 当前地点 / 用户问题 → 检索节点 → 相关原文片段 → Context Compiler → LLM;
- **世界事实与世界知识分离**:世界状态回答"现在发生了什么",规则图回答"什么情况下允许发生什么",知识库回答"这个世界本来是什么样",LLM 只回答"如何表达"——每一种信息都有明确的来源与生命周期;
- **同一知识资产可以被不同节点以不同方式消费**:角色记忆节点、角色背景检索节点、世界观检索节点、剧情验证节点、对话上下文节点各取所需;
- 可组合成**事实验证节点**:LLM 生成候选内容 → 事实提取 → 知识库检索 → 事实验证 → 一致则接受 / 不一致则修正或拒绝——LLM 不再是唯一的知识裁判(见 [应用模式与场景图式](./graph-application-patterns.md) §7)。

### 2.3 数据(模型)资产:以人格矩阵为例

**节点定义"如何使用人格模型",人格矩阵资产定义"这个人格模型本身是什么"**。两者分离后,"善良""谨慎""自私"等特质成为**可持久化、可比较、可复制、可组合的数据资产**,而不是提示词里的形容词:

```
PersonalityAsset
├── identity
├── dimensions(维度)
├── bias_matrix(偏置矩阵)
├── initial_state(初始状态)
├── update_rules(更新规则)
├── constraints(约束)
└── metadata
```

- **生产链**:训练文本(一本小说 / 作者长期作品 / 角色历史对话 / 人工行为案例)→ 文本分析与特征提取 → 人格特征空间 → 矩阵拟合 → 资产 → 注册到资产系统 → 人格节点引用;
- **版本化与可替换**:`Benevolent@1.0` / `Benevolent@2.0` / `Ruthless@1.0`——旧存档可以继续使用旧人格资产,新世界升级新版本;同一角色只需在编辑器里换引用;
- **可组合**:基础人格 + 文化人格 + 职业人格 + 当前阶段人格 + 关系偏置 + 短期心理状态,经节点组合产生实际行为;
- **可测试性**:同一世界 + 同一规则 + 同一状态 + 同一 RNG + 不同人格资产 → 行为轨迹差异,**差异可归因于人格模型本身**——比"换一个 system prompt 看看是不是更善良了"严格得多;
- **理论边界**:人格矩阵**不承担"善恶真理"的定义**,它只表达"在给定状态、目标、关系和环境下,这个角色倾向于如何评价不同的行为";什么行为最终发生,仍由决策节点、世界规则、资源约束、随机性共同决定。若人格矩阵直接等价于"善良 = 永远帮助别人",它就退化成新的 Prompt 工程(见 [人格、意图与认知链](./graph-cognitive-chain.md) §6)。

### 2.4 媒体资产:表现资源包

立绘、表情、背景、音频、视频都是媒体资产,由表现层按状态引用,而不是由 LLM 决定:

```
CharacterVisualAsset
├── character_id
├── sprites { neutral, happy, sad, angry, afraid, ... }
└── metadata
```

情绪状态 → 表情矩阵节点 → `expression = afraid` → 角色表现节点 → `sprite = fran/afraid.png`。**LLM 管台词,程序管表情,前端管渲染**——视觉表现不随 LLM 措辞采样漂移(见 [表现状态与输出适配](./graph-presentation-output.md))。

## 3. 全局变量

全局变量是**命名状态槽**,是"数据不走黑板"原则的唯一例外,受以下约束收敛:

### 3.1 声明

- 必须声明(名字 + 类型 + **默认值**)才能被引用;
- **未声明引用 → 编辑事务提交时抛异常**,运行时加载图资产时再校验一遍(防手工改资产文件绕过编辑器)。

### 3.2 语义

- **读取不唤醒**:全局被改不触发任何节点;读取它的节点在下次因其他原因开火时取最新值(拉,不是推);
- **写入**经输出端口的全局写入绑定完成,轮末统一提交;
- **多写者:last-write-wins**——轮内按节点在图资产中的声明顺序应用,后者覆盖前者;跨轮按轮次自然有序;同一节点多个输出写同一全局 → 校验报错。编辑器对多写者给出告警(编辑层的提示责任),运行时不做硬限制;
- **轮初读、轮末提交**:单写者场景下写入顺序与节点执行顺序无关;多写者是唯一的保序依赖,属编辑器应提示避免的边缘路径。

## 4. 资产相关校验(编辑事务提交前)

1. 所有绑定引用的资产(全局变量/常量/服务)已声明(否则抛异常);
2. 全局变量声明必须带默认值;
3. 输出绑定指向的资产必须存在;
4. 同一节点多个输出绑定同一全局 → 报错。

完整校验清单见 [持久化与编辑](./graph-persistence-and-editing.md) §5。

## 5. 资产与运行时

- 资产是数据:编辑器是资产的第一个消费者,运行时是第二个——**资产格式先于编辑器存在**,编辑器只是"图数据的可视化编辑界面";
- 资产可分享、可打包、可版本化;节点类型资产与图资产分离,类型可复用;
- 图资产中的声明顺序承载全局写序语义,资产格式必须保留声明顺序。
