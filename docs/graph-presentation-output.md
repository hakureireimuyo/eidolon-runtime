# 表现状态与输出适配:世界与表现的分层

> 本文档定义系统的输出边界:**运行时不负责"怎么呈现世界",它只负责产生可消费的状态与信号;前端只是这些输出的一个消费者。** 世界模拟与表现形式彻底分离。
> 相关文档:图运行时总纲(`eidolon-graph` 仓库 `docs/graph-runtime-overview.md`) · 资产系统(`eidolon-graph` 仓库 `docs/graph-assets.md`) · [应用模式与场景图式](./graph-application-patterns.md)

## 1. 核心命题

> **LLM 只是文本表现器,系统真正需要产生的是一个更高层的"表现状态";表现状态经输出适配器流到任意表现终端。**

```
世界事实 → 内部推理/状态转换 → 表现状态 → 输出适配器
```

以"吃药进入血肉世界"为例:

```
世界事实:   player.took_medicine = true
世界状态:   world.mode = horror
表现状态:   background = hospital_horror
            character.expression = fear
            music = distorted
具体输出:
    Web       → 切换 CSS / 背景 / 立绘 / 音频
    Terminal  → 文本 + ANSI
    TTS       → 恐惧语气的语音
    Image     → 调用图片生成节点
    Game      → 修改场景和 Sprite
```

前端不需要知道"吃药"这个游戏机制,它只做一件事:**状态 → 呈现**,甚至可以完全不知道这些状态是怎么产生的。

## 2. 表现状态与输出节点

- `[Presentation State]` 是图中的普通节点/子图:消费世界状态,产出声明式的表现快照;
- 输出适配器(`Web UI` / `TUI` / `图片生成器` / `音频` / `视频`)都是**输出节点**,由控制信号决定是否调用——接入生图、视频模型的位置因此非常自然:
  - 生成模型是**昂贵行动者**,只在状态触发 + 门控开启时调用(对齐既有文档"由状态触发,而非 LLM 决定");
  - 运行时完全不需要知道最终接的是网页、终端、手机、游戏客户端还是未来的 VR 前端;
- 生成的视觉内容同样是**状态的投影**:不保存 `avatar.png`,保存 `appearance_state{emotion, weather, lighting, clothing}`,图片/视频/3D 都从该状态渲染——模型替换不影响数据层。

## 3. 表情矩阵与立绘

```
[情绪状态] → [Emotion → Expression Matrix] → expression = afraid
      → [角色表现节点] → sprite = fran/afraid.png
```

- **LLM 不需要决定"应该显示什么表情"**:LLM 管台词("我……不想再看到那个东西。"),程序状态管表情(`emotion = fear → expression = afraid`),前端管渲染(加载 `afraid.png`);
- 最终视觉表现不会因为 LLM 今天采样出了不同措辞,就随机出现完全不同的表情;
- 立绘、表情、背景资源包是媒体资产(见 资产系统(`eidolon-graph` 仓库 `docs/graph-assets.md`) §2.4),按状态引用。

## 4. 同一世界,多种体验方式

同一个 `.cart` 世界,可以:

```
文字冒险前端       → 只消费文本输出
视觉小说前端       → 文本 + 背景 + 立绘 + 表情 + BGM
第一人称探索前端    → 场景 + 物品 + 地图 + 文本
第三方客户端       → 自己解释同一套世界输出
```

**图本身完全不需要因为换前端而重写**——世界模拟和表现形式彻底分离。

## 5. 定位更新

- "LLM 是渲染器"的更准确说法:**LLM 是文本表现器**;系统真正产生的是表现状态;
- 在这个定义下:聊天只是一个非常特殊的前端,人格只是一个非常特殊的节点网络(见 [人格、意图与认知链](./graph-cognitive-chain.md)),RAG 是一种知识节点,LLM 是一种昂贵的生成节点,视觉资源包是资产,表情矩阵是状态到表现的映射,游戏剧情/解谜/地图/背包/NPC/时间系统则都是图中的数据和节点(见 [应用模式与场景图式](./graph-application-patterns.md));
- 系统的最终形态:**一个能够用图定义世界、用节点运行世界、用资产提供世界内容,并把世界状态输出给任意表现终端的通用世界运行时。**
